Project name
FollowThrough

Tagline
Catch missing requirements and unsupported promises before your proposal goes out.

Track
Best Apps and Agents

Business problem
Small software agencies reconcile RFPs, clarification emails, company evidence and client amendments manually. Missing a mandatory attachment or using an outdated delivery requirement can leave a proposal incomplete. Unsupported capability promises can create delivery risk. FollowThrough is a local review workspace for the person accountable for the final package.

What it does
Import selected PDF, DOCX or text sources. NVIDIA Nemotron 3 Nano on Nebius Token Factory extracts proposed requirements and deadlines. Application code anchors exact quotations, leaving interpretations and ambiguous dates for human review. Approved company evidence is matched into conservative verbatim drafts. Missing answers, attachments, stale evidence and unsupported text remain visible. Client amendments preserve source history and reopen review. Approval binds an exact package revision and content hash. Export includes a client-facing DOCX and separate internal review material. External submission, receipt evidence and acknowledgement remain separate states.

How we built it
React and Vite frontend, FastAPI backend, SQLite transactions, strict Pydantic schemas, bounded document parsing, and a deterministic proposal orchestrator. Nebius provides the real inference API; nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B interprets selected source text. No provider call is required for the explicitly labelled guided fixture walkthrough. Live analysis never falls back to fixtures.

Why this is agentic
The system moves work through extraction, evidence retrieval, gap identification, amendment review, approval and export while preserving state and audit history. The model proposes requirements; code enforces evidence and approval boundaries. We deliberately use lexical retrieval and verbatim evidence drafts rather than presenting unsupported prose as a completed proposal. No autonomous external submission is implemented.

Testing
13 standalone automated checks passed (plus two development-only starter checks), including two end-to-end proposal contracts with real SQLite and API calls. Six small fictional live NVIDIA examples passed schema, exact-quotation and keyword-based expected-requirement checks. These are smoke tests, not a claim of 95% production accuracy. The application source view was also tested through a live model call in the browser.

Challenges
Initial live requests returned extra fields, truncated responses and incorrect character offsets. We made the schema explicit, requested JSON, disabled unnecessary thinking for Nano extraction, and moved citation-offset calculation into code. Unknown or ambiguous quotations fail closed. Model omissions and semantic misinterpretation remain possible, so users review requirements and evidence relevance.

Nebius and NVIDIA feedback
Nebius's OpenAI-compatible HTTP API made integration straightforward. The model catalog endpoint successfully identified available NVIDIA models. Nemotron 3 Nano handled six small requirement-extraction cases with approximately 1 to 2 second latency after changing the inference configuration. Earlier reasoning-enabled requests consumed far more output budget and could truncate. Exact numeric citation offsets were unreliable; code-based quotation anchoring was more appropriate. The onboarding credit form initially did not load in the automated browser, and the emailed code arrived later. Credits were successfully redeemed. We would use this stack again for bounded extraction with deterministic validation and human review; these observations do not establish general model quality or throughput.

Limitations
Single-owner local test build, not a public multi-tenant service. No measured customer impact, contract-win improvement or time savings. Visual transcription requires human verification; no arbitrary spreadsheet ingestion, autonomous submission or legal-compliance guarantee. Evidence retrieval supports local keyword matching or Qwen embeddings followed by NVIDIA relevance assessment. Relevance is reviewed by a person. Gmail OAuth is optional and remains unverified; the main journey works with documents and pasted emails. Receipt authenticity is not independently verified. User exceptions are explicit and auditable. No real client documents are included in the demo.

Future work
Customer interviews, permissioned real-RFP pilots, broader labelled evaluation, stronger semantic-retrieval quality measurement, and authenticated organization-scoped deployment before any public service exposure.

Version 0.3 additions
Semantic search uses Qwen/Qwen3-Embedding-8B to shortlist approved evidence and NVIDIA Nano to assess relevance. The documented dedicated Qwen reranker returned 404 on this account, so we explicitly use chat-based reranking. NVIDIA Nemotron-3.5-Super-VL transcribes scanned pages and tables; users must verify the text against originals before analysis. NVIDIA Super performs optional deeper conflict review with thinking enabled, exact source citations and recorded human dispositions. Unresolved findings and outdated reviews block approval/export. Three fictional live smoke cases passed; these are not broad accuracy measurements. The public 2:30 video shows the v0.2 core workflow; additional screenshots document these new features.

Version 0.4 additions
A source-to-approval impact map shows original and amended requirements, selected evidence, answer review, attachments and missing-input owners. The default Before you submit screen groups actionable blockers and advisory follow-ups. The same readiness contract controls the screen, approval, export and user-reported submission; expired evidence can reopen readiness even without a content change. All added map edges are derived from stored associations, not an inferred claim of completeness. Customer pilots, comparative review-time measurement and a broader labelled evaluation remain outstanding.


Version 0.5 / judge and reliability improvements
An optional invitation-gated judge launcher now requires one HTTPS origin, Secure/HttpOnly cookies, an expiry and a persistent provider-attempt ceiling. Gmail is disabled in that shared fictional workspace. This is implemented and tested, not deployed: no existing free server has been identified. The public Pages site remains a zero-inference-cost fictional walkthrough. Do not describe it as a live model service.

The deadline guard keeps guessed source precision unresolved. A retained-prompt run on 16 author-labelled synthetic development cases passed 12 raw complete cases, with 18/20 labelled requirement recall, 18/19 labelled precision, and 19/19 source-locatable requirement quotations. Applying the deterministic deadline guard to those saved outputs passed 14/16 complete cases and 16/16 deadline checks. Quote validity is not semantic accuracy. Two extraction failures remain. A repeated candidate prompt increased false positives and was rejected; both runs are public. These are development results, not an independent benchmark or customer outcome evidence.

Nineteen standalone automated checks passed, including HTTPS invitation/session/expiry checks and real HTTP retry accounting against a persistent SQLite allowance.
